# 한컴독스 브라우저 편집 (기본)

한컴독스 웹 한글은 본문을 canvas로 그리므로 DOM으로 글을 읽거나 클릭한 곳에 입력하는 방식이 통하지 않는다. 아래 방법만 안정적으로 동작한다(2026-09, macOS 크롬 실측). 다른 OS·브라우저는 아직 검증되지 않았다. 단축키의 `cmd`를 `ctrl`로 바꿔도 되는지 확실하지 않으니, 먹지 않으면 유저에게 알리고 메뉴로 대신한다.

이 스킬은 묶음의 기본이다. 이어지는 작업은 다음 스킬이 맡고, 둘 다 이 문서의 0~2절을 전제로 한다.
- `hancomdocs-paste`: hwpable-html HTML 붙여넣기, 표 '글자처럼 취급', 표 줄 간격·폭
- `hancomdocs-format`: 손으로 친 □/◦/- 기호를 진짜 단계 서식으로 정리, 자간으로 줄 넘침 정리

**실행 환경**: 모든 단계에 Claude in Chrome 확장이 필요하다. 로컬 셸이 필요한 단계(1절 클립보드 읽기 스크립트)는 Claude Code에서만 되고, 지금은 macOS 전용이다(`pbpaste`·`osascript`). 셸이 없거나 macOS가 아니면 이렇게 대신한다.
- 문서 읽기: 1절 대신 찾아 바꾸기의 **다음 찾기**로 필요한 문구를 하나씩 확인하고, 긴 구간은 유저에게 복사해 채팅에 붙여 달라고 한다.

## 0. 준비

1. `claude-in-chrome` 스킬을 먼저 불러오고, 크롬 도구가 지연 로드 상태면 ToolSearch 한 번으로 한꺼번에 불러온다: `tabs_context_mcp, navigate, computer, find, read_page, javascript_tool, browser_batch, tabs_create_mcp, tabs_close_mcp`.
2. `https://www.hancomdocs.com`로 이동한다. 유저 크롬 프로필이라 로그인돼 있다. 최근 문서 목록에서 대상 문서를 클릭하면 새 탭(`webhwp.hancomdocs.com/webhwp/?mode=HWP_EDITOR...`)으로 열린다. 문서가 여러 개면 제목·수정 시각으로 고르고, 애매하면 유저에게 묻는다. webhwp 주소를 직접 `navigate`하면 "문서 주소가 올바르지 않습니다"로 안 열린다. 늘 홈의 문서 카드를 눌러 연다. 카드 제목을 `find` 참조로 누르면 안 열릴 때가 많으니, 스크린샷을 찍고 카드 썸네일을 좌표로 누른다. 새 탭은 `tabs_context_mcp`로 ID를 받는다.
   - 오른쪽 위 "편집 (2)"처럼 숫자가 2 이상이면 다른 사람(유저 포함)이 같은 문서를 편집 중이다. 유저에게 알리고, 실전 문서에서는 읽기만 할 때도 찾아 바꾸기·붙여넣기를 누르지 않는다.
3. 편집 전에 유저에게 정한다(AskUserQuestion):
   - 변경 기록을 켤지 여부. 권장은 켜기로, **검토 → 변경 내용 추적 → 변경 내용 추적** 메뉴에서 켠다. 상태표시줄에 "변경 내용 [기록 중]"이 빨갛게 뜨면 켜진 것이다.
   - 통째로 지울 블록(기관 소개 절, 폐기된 단락 등)을 지울지 여부
   - 표지·서명란처럼 새 정보(기관장·담당자 연락처)가 필요한 칸

## 1. 본문 읽기: 클립보드 경유 (macOS + Claude Code)

1. 찾아 바꾸기로 **표 밖 본문 문단**에 커서를 둔다(2절 참고). 표·글상자 안에 커서가 있으면 cmd+a가 그 칸만 잡는다.
2. `cmd+a` → `cmd+c` → 곧바로 `cmd+Up`을 누른다. 전체 선택을 풀지 않은 채 입력하면 문서 전체가 덮어써지므로 반드시 푼다.
3. 이 스킬 폴더(스킬을 불러올 때 알려 주는 base directory)의 스크립트로 로컬에서 읽는다:
   ```bash
   bash <이 스킬 폴더>/scripts/read_clipboard.sh <scratchpad>/doc_v1
   ```
   이 스크립트는 `doc_v1.txt`(평문)와 `doc_v1.cell.txt`를 만든다. `doc_v1.cell.txt`는 HTML을 풀어 칸 안 줄바꿈을 `⏎`, 문단 끝을 `¶`로 표시한 파일이다.
4. 문서가 표지·요약·본문 등 여러 글상자로 나뉘어 있으면 1~3을 영역마다 반복한다. 한 번에 약 9만 자처럼 일부만 잡힐 수 있으니 글자 수를 확인한다.
5. 기준 자료(프로젝트 CLAUDE.md, 유저가 준 변경 목록 등)와 대조해 바꿀 목록을 적고 유저에게 보여 준다.

## 2. 편집: 찾아 바꾸기 대화상자만 쓴다

- 여는 법: `cmd+shift+h`(편집 → 찾기 → 찾아 바꾸기). `find`로 참조를 얻는다: 찾을 내용, 바꿀 내용, 아래로, 위로, 문서 전체, 바꾸기, 다음 찾기, 모두 바꾸기, 닫기. 참조 ID는 세션 동안 유지된다.
- 한 건 처리: 찾을 내용 칸을 triple_click한 뒤 type → 바꿀 내용 칸을 triple_click한 뒤 type → **모두 바꾸기** 순서로 한다. 결과 문구("바꾸기를 N번 했습니다" / "찾는 내용이 없습니다")는 대화상자 아래쪽을 zoom해서 확인한다. 여러 건은 `browser_batch`로 묶는다.
- 특정 한 곳만 바꿀 때: 고유한 이웃 문구로 **다음 찾기**를 해서 커서를 옮긴다. 그다음 방향(아래로/위로)을 정하고 대상 문구로 **다음 찾기** → 스크린샷으로 선택 위치 확인 → **바꾸기** 순서로 한다. 바꾸기를 누르면 선택이 다음 일치로 넘어간다. 따라서 이어지는 검색은 기준점을 다시 잡고 한다.
- 지우기: 찾아서 선택한 뒤 대화상자를 닫고 `Delete` 키를 누른다. 키 입력(Delete, Tab, 방향키, Home/End)은 먹는다.

### 키보드 우선(속도)

마우스로 메뉴를 하나씩 누르면 느리다. 먹는 것이 확인된 키는 키보드로 한다(2026-09-29 macOS 크롬 실측).

| 할 일 | 키 |
|---|---|
| 문단 전체 선택 | 문단 안에서 `Home` → `shift+Down`(줄 수만큼) → `shift+End` |
| 여러 문단 선택 | 첫 문단 첫머리 클릭 → 끝 문단 끝 shift+클릭, 또는 `shift+Down` 반복 |
| 모양 복사 대화상자 | `alt+c`(편집 → 모양 복사와 같은 대화상자) |
| 자간 좁게 / 넓게 | `alt+shift+n` / `alt+shift+w`(한 번에 1%) |
| 찾아 바꾸기 | `cmd+shift+h` |
| 복사·붙여넣기·되돌리기 | `cmd+c` · `cmd+v` · `cmd+z` |

- **같은 키를 연달아 보낼 때는 1초씩 쉰다.** `key`의 `repeat`나 한 번에 여러 키를 보내면 첫 번째만 먹고 나머지가 빠진다(자간 3번 → -1%만 적용, shift+Down 4번 → 한 줄만 선택). `browser_batch` 안에서 키 → `wait 1` → 키 순서로 보낸다.
- 한글 단축키 중 `ctrl+shift+n`(자간)은 먹지 않았다. 맥 크롬에서는 `alt+shift+n`이다.

### 함정

- **캔버스에 한글을 직접 입력하지 않는다.** 글자가 빠지거나 전혀 들어가지 않는다. 새 칸을 채울 때는 영문 임시 문자열(QP1, QP2 등, 서로 부분 문자열이 되지 않게)을 입력하고 찾아 바꾸기로 한글로 바꾼다.
- **마우스 클릭은 방금 찍은 스크린샷 좌표로만 한다.** 본문 글자·표 칸 클릭과 shift+클릭 범위 선택은 된다. 다만 크롬 창 크기와 스크린샷 배율(1568폭·1425폭 등)이 작업 중에 바뀌어 옛 좌표는 빗나간다. 확실한 커서 이동은 찾기 결과와 방향키로 한다.
- **선택 영역이 남아 있으면 찾기가 "찾는 내용이 없습니다"로 실패한다.** 모양 복사·범위 선택 뒤에는 `Right`나 본문 클릭으로 선택을 푼 다음 찾는다.
- **변경 기록 중에는 지운 글자도 검색된다.** 모두 바꾸기 검색어가 이미 지운 문장과 겹치면 지운 글자 안에 새 글이 끼어든다. 검색어는 이미 지운 문장과 겹치지 않는 고유 문구로 잡는다. 실수했으면 곧바로 `cmd+z`를 누른다(모두 바꾸기 한 번이 되돌리기 한 번에 되돌아간다).
- **표 칸 안 줄바꿈(`⏎`)을 넘는 검색은 안 된다.** "(주)A⏎(부)B" 같은 칸은 줄별로 따로 바꾼다. 구조는 `.cell.txt`에서 확인한다.
- **긴 문구, 기호 `·`·`→`·`—`를 넣은 검색은 된다.** 바꿀 내용을 비워 둔 채 바꾸면 삭제가 된다.
- **F5를 누르지 않는다.** 크롬 도구가 F5를 브라우저 새로 고침으로 보낸다. 세 번 연속 누르면 "문서를 열 수 없습니다"가 떠서 탭을 닫고 홈에서 다시 열어야 했다. 한글의 셀 블록(F5)은 마우스 드래그로 대신한다.
- **cmd+T를 누르지 않는다.** 문단 모양 단축키지만 크롬 새 탭이 열린다. 서식 → 문단 모양 메뉴를 쓴다.
- **메뉴는 좌표가 아니라 `find` 참조로 누른다.** 찾기·편집 뒤 화면 전체가 10px쯤 위로 밀려 좌표 클릭이 글꼴 칸 같은 엉뚱한 곳에 맞는다. `find`로 `서식`·`표` 상단 메뉴, `문단 모양...`, `표/셀 속성...` 참조를 받아 쓴다.

## 3. 표 구조 편집

- 행 추가·삭제: 찾기로 해당 행에 커서를 둔 뒤 **표 메뉴 → 줄/칸 추가하기 → 아래쪽에 줄 추가하기**, 또는 **줄/칸 지우기 → 줄 지우기**를 쓴다. 이 작업은 **변경 기록에 남지 않으므로** 유저에게 따로 알린다.
- 새 행의 칸 이동: 마지막 칸에서 `Home` → `Left`를 누르면 앞 칸으로 간다. shift+Tab은 첫 번째만 동작했다.
- 큰 표 개체(기관 소개 박스 등): 표 테두리를 클릭하면 개체로 선택되지만, 변경 기록 중에는 `Delete`로 지워지지 않았다. 유저에게 직접 지우라고 안내한다.

## 4. 마무리 검증

1. 1절 방법으로 각 영역을 다시 복사해, 없애기로 한 표현(옛 기관명, 옛 수치 등)을 grep으로 다시 찾는다. 셸이 없으면 찾아 바꾸기의 **다음 찾기**로 하나씩 "찾는 내용이 없습니다"를 확인한다.
2. 임시 문자열(QP·QQ 등)이 남지 않았는지 확인한다. 서식정리를 했으면 `hancomdocs-format`의 검증 항목도 본다.
3. 보고에 넣을 것: 고친 범주별 요약, 변경 기록에 남지 않은 표 구조 변경, 브라우저로 못 한 항목(직접 할 일), 유저 정보가 필요한 칸.
4. 작업용으로 연 한컴독스 홈 탭은 닫고, 문서 탭은 유저가 검토하도록 열어 둔다.
