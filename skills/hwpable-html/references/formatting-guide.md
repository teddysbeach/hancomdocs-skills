# HWP-able HTML 서식 변환 가이드

이 문서는 유저 텍스트를 HWP 호환 HTML로 변환할 때 따르는 모든 규칙을 담고 있다.

---

## 1. 구조 뎁스 체계

두 가지 서식 스타일을 지원한다. 유저에게 먼저 선택을 받는다.

### 스타일 A: 디폴트형 (ㅁ > ㅇ > -)

한국 공문서·보고서의 기본 3단계 들여쓰기 구조.

| 뎁스 | 클래스 | 딩뱃 기호 | 들여쓰기 | HTML 예시 |
|------|--------|-----------|----------|-----------|
| 1 (대항목) | `item-1` | ㅁ | 16px | `<div class="item-1">ㅁ 추진 배경</div>` |
| 2 (중항목) | `item-2` | ㅇ | 32px | `<div class="item-2">ㅇ 세부 내용임.</div>` |
| 3 (소항목) | `item-3` | - | 48px | `<div class="item-3">- 상세 항목임.</div>` |

### 스타일 B: 올드형 ((가) > ① > ㉮)

전통 공문서 번호 체계. 각 뎁스 내에서 항목 순서에 따라 기호가 순차 증가한다.

| 뎁스 | 클래스 | 딩뱃 기호 | 들여쓰기 | HTML 예시 |
|------|--------|-----------|----------|-----------|
| 1 (대항목) | `item-1` | (가), (나), (다), (라)… | 16px | `<div class="item-1">(가) 추진 배경</div>` |
| 2 (중항목) | `item-2` | ①, ②, ③, ④… | 32px | `<div class="item-2">① 세부 내용임.</div>` |
| 3 (소항목) | `item-3` | ㉮, ㉯, ㉰, ㉱… | 48px | `<div class="item-3">㉮ 상세 항목임.</div>` |

### 뎁스 적용 원칙

- 유저 텍스트의 제목·소제목·본문 계층을 파악하여 적절한 뎁스를 부여한다.
- 대주제(섹션 제목) → item-1, 설명·본문 → item-2, 세부 사항·열거 → item-3이 일반적이다.
- 유저가 명시적으로 구조를 잡아둔 경우(번호, 들여쓰기 등) 그 구조를 존중한다.
- item-1 블록이 끝나면 `<br/>`로 시각적 분리를 넣어 섹션 간 여백을 확보한다.

### 중항목(item-2) 작성 규칙

대항목 아래 중항목이 여러 개 이어질 때, 첫 번째 중항목에서 해당 섹션 전체를 요약하는 문단(2~3문장)을 먼저 서술하면 가독성이 높아진다. 유저 텍스트에 이미 요약 문단이 있으면 그대로 사용하고, 없으면 추가하지 않는다(내용 생성 금지 원칙).

## 2. 항목 기호 규칙

### 딩뱃 기호 (ㅁ, ㅇ, -)

모든 뎁스의 텍스트 시작 부분에 해당 뎁스의 딩뱃 기호를 붙인다. 이는 한국 공문서 관행을 따른 것이다.

### 순서 기호 (①②③④)

순서 기호는 **우선순위·절차·흐름·단계**가 존재하는 경우에만 사용한다. 단순 나열에는 사용하지 않는다.

```html
<div class="item-3">
  <div>① 데이터 수집 및 전처리</div>
  <div>② 모델 학습 및 검증</div>
  <div>③ 서비스 배포 및 모니터링</div>
</div>
```

## 3. 서술 vs 테이블 판단

**서술(문단형)이 기본**이다. 테이블은 아래 조건을 충족할 때만 사용한다.

### 테이블 사용 O (아래 중 하나라도 해당)

- 항목 간 **비교·대조**가 필요한 경우
- 동일한 속성을 가진 정보가 **2개 이상 반복**되는 경우 (예: 이름-역할-기간)
- **수치, 일정, 역할, 구분값** 등 정형 데이터
- 요약 표, 현황 표, 계획 표, 일정 표, 역할 분담 표

### 테이블 사용 X (아래에 해당하면 문단형 서술)

- 개념 설명, 배경 설명, 문제 인식, 기대 효과
- 문맥 흐름이 중요한 문장형 설명
- 비교 필요 없는 단순 나열
- 1~2줄로 충분한 내용

> "목록이니까 테이블"이라는 판단은 금지. 비교·반복·정형 데이터 여부로 판단한다.

## 4. 테이블 작성 규칙

### 허용 태그

`<table>`, `<tr>`, `<th>`, `<td>`만 사용한다. `<thead>`, `<tbody>`, `<caption>`은 HWP 붙여넣기 시 무시되거나 깨질 수 있으므로 사용하지 않는다.

### 배치 규칙

테이블은 반드시 `<div class="item-X">` 내부에 배치한다. 테이블 제목이 있으면 같은 div 안에 함께 둔다.

```html
<div class="item-3">
  <div>① 사업 추진 현황</div>
  <table>
    <tr>
      <th>구분</th><th>목표</th><th>실적</th><th>달성률</th>
    </tr>
    <tr>
      <td>매출</td><td>100억</td><td>95억</td><td>95%</td>
    </tr>
  </table>
</div>
```

### 크기

- 테이블 최대 폭은 560px이며, 뎁스에 따라 자동 축소된다 (스크립트가 처리).
- th는 내용에 맞는 최소 폭, td는 내용 길이에 비례하여 자동 조정된다.

### 이미지 삽입

```html
<td><img src="이미지경로" alt="설명" width="200" height="150"></td>
```

width/height를 반드시 명시한다. HWP는 이 속성 없이 이미지 크기를 판단하지 못한다.

### special-finish (임팩트 강조)

핵심 성과나 결론을 강조하려면 `special-finish` 클래스를 사용한다.

```html
<div class="item-3">
  <table>
    <tr><th class="special-finish">정량목표 15건 중 15건 달성 (100%)</th></tr>
  </table>
</div>
```

### 금지 사항

- 불필요한 테이블 분할 금지
- 한 데이터셋을 여러 테이블로 쪼개지 않는다
- 빈 행·빈 열 삽입 금지

## 5. HWP 호환성 핵심

HWP(한글)에 HTML을 복사·붙여넣기했을 때 서식이 최대한 유지되도록 아래 사항을 지킨다.

### 폰트

- 기본 폰트: `맑은고딕` (Malgun Gothic)
- 크기 단위: 반드시 `pt` 사용 (`px`, `em`, `rem` 금지)
- 본문: `10pt`, 테이블 내부: `9pt`

### 테이블

- `border-collapse: collapse` 필수
- 테두리: `1px solid` (색상은 프리셋에 따름)
- `display: inline-table`로 텍스트 흐름 속에 배치
- `<colgroup>`, `<col>` 태그 사용 금지 (HWP에서 무시됨)
- 열 폭을 반드시 고정해야 하는 표(구성도 등)는 셀의 `width` 속성으로 지정한다 → `references/org-chart.md`

### 레이아웃

- `margin`, `padding`은 `px` 단위만 사용
- `flexbox`, `grid`, `float` 사용 금지
- `<div>` + `margin-left`로 들여쓰기 처리
- `<br/>`로 줄바꿈, `<p>` 태그 대신 `<div>` 사용

### 기타

- CSS 클래스는 `<style>` 태그에 정의 (인라인 스타일 최소화)
- JavaScript는 브라우저 미리보기용. HWP에는 영향 없음
- 툴바·본문 복사·표 폭 고정은 `scripts/add_toolbar.py`가 넣는다(`templates/toolbar.html`). 표 폭은 CSS가 아니라 셀 `width` 속성으로 고정돼야 HWP에서 유지된다.
- 붙여넣지 않을 안내 문구(삽입 위치 등)는 `<div class="guide">`로 감싼다. 본문 복사 버튼이 자동으로 뺀다.
- `line-height: 1.6` 유지 (HWP 기본 줄간격과 유사)

---

## 6. 문장 스타일

- 불필요한 구어체 표현 금지 (보고서·공문서 톤 유지)
- item-1 블록 종료 후 `<br/>` 삽입으로 섹션 간 시각적 분리
- 유저가 제공한 말투·어미를 그대로 유지 (변환 금지)
