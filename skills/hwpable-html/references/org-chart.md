# 구성도(추진조직표) 모드

사업계획서의 `추진체계`, `추진조직`, `컨소시엄 구성도`처럼 **위에서 아래로 갈라지는 조직도**를 HWP에 붙여 넣을 수 있는 표로 그린다. 이미지가 아니라 표라서 HWP에서 글자를 바로 고칠 수 있다.

## 언제 쓰나

- 유저가 조직도·구성도·추진체계도·추진조직표를 HWP용으로 요청할 때
- 유저가 준 조직도 이미지·텍스트 메모를 표로 옮길 때 (구조와 문구는 유저 것을 그대로 쓴다)
- 셀 병합만 한 평면 표로는 "위계"가 안 보인다는 피드백이 있을 때

## 모양 원리

- 격자: 맨 아래 단계의 상자 하나를 `슬롯`으로 보고, 슬롯마다 `[빈 열][칸][칸][빈 열]` 4열을 둔다. 상자 사이는 빈 열 2개만큼 떨어져 **따로 떨어진 상자**로 보인다.
- 상자: 칸 병합(`colspan`)으로 만든다. 상위 단계는 슬롯 여러 개를 덮는 넓은 상자, 하위 단계는 슬롯 하나짜리 상자.
- 연결선: 상자 사이의 **빈 행**에서 빈 칸의 `border-right`(세로선)와 `border-top`(가로선)으로 ┬ 모양을 그린다.
  - 부모 중심에서 세로선 1행 → 다음 행 윗선으로 자식 중심들을 잇고, 자식 중심마다 세로선.
- 구간(section): 트랙·분과처럼 성격이 다른 묶음은 `band` 띠(전체 폭, 진한 회색)로 이어 한 표 안에 쌓는다.
- 색: 상위 단계 상자는 회색(`#EEEEEE`, th), 하위 단계와 요약 상자는 흰색, 띠는 `#D9D9D9`. 프리셋 색을 쓰려면 spec의 `colors`로 바꾼다.

## HWP 호환 규칙 (중요)

| 항목 | 규칙 | 이유 |
|---|---|---|
| 열 폭 | 맨 위 **눈금 행**(높이 1px, 빈 칸)에 `width` 속성으로 지정 | HWP는 `<colgroup>`·CSS 폭을 무시하고 셀 `width` 속성은 따른다 |
| 테두리·배경 | 셀마다 **인라인 style** | 템플릿의 `td { border }` 규칙이나 이중선 규칙과 충돌하지 않게 |
| 표 표시 | `<table data-orgchart="1">` | base.html의 폭 자동조정 스크립트가 이 표는 건너뛴다 |
| 연결선 행 | 높이 10px, 글자 1pt | HWP가 빈 행을 줄 높이만큼 키우는 것을 최소화 |
| 긴 이름 | 2칸 상자에 7자 이상이면 `\n`으로 줄을 나눈다 (`기관B\n연구소A`) | 좁은 상자에서 글자가 테두리에 닿음 |

붙여 넣은 뒤 연결선 행이 벌어져 보이면 HWP에서 해당 행만 선택해 높이를 줄이면 된다.

## 생성기 사용

손으로 24열 격자를 짜지 말고 `scripts/orgchart.py`를 쓴다.

```bash
python3 scripts/orgchart.py spec.json > table.html        # <table> 조각 → 본문에 삽입
python3 scripts/orgchart.py spec.json --page -o preview.html   # 단독 미리보기
```

### spec.json

```json
{
  "width": 560,          // 표 전체 폭(px). item-3 안이면 약 520~560
  "font_pt": 10,         // 상자 글자 크기. 문서 본문 크기에 맞춘다
  "gap_px": 8,           // 빈 열 폭(선택)
  "root": {"title": "사업 총괄", "sub": "업체A · 총괄책임자"},
  "side": {"title": "외부 자문", "sub": "기관A"},
  "sections": [
    {"nodes": [
      {"title": "과제1 · 프로젝트A", "sub": "업체A · 책임자",
       "children": [{"title": "업체B", "sub": "개발"},
                    {"title": "업체C", "sub": "검증"}],
       "detail": "프로젝트A 개발\n1차년도 완료"}
    ]},
    {"band": "▼ 전 과제 공통 지원 ▼",
     "nodes": [{"title": "기술지원반", "sub": "운영 · 장애 대응", "children": [...]}]}
  ],
  "colors": {"head": "#EEEEEE", "band": "#D9D9D9", "line": "#000000"}
}
```

| 키 | 뜻 |
|---|---|
| `root` | 맨 위 상자(가운데) |
| `side` | 맨 위 오른쪽의 점선 성격 보조 상자(협의창구·자문 등). 공간이 없으면 생략됨 |
| `sections[].nodes` | 그 구간의 1단계 상자들. 첫 구간은 root에서 갈라진다 |
| `children` | 1단계 상자 아래 2단계 상자들(보통 2~3개) |
| `detail` | 자식 아래로 모이는 요약 상자(수행 내용·시점 등). 선택 |
| `slots` | 자식이 없거나 적은 노드의 상자 폭(슬롯 수). 예: `"slots": 2` |
| `band` | 둘째 구간부터, 앞 구간과 잇는 전체 폭 띠 문구 |

- 구간마다 슬롯 수가 다르면 적은 쪽이 가운데로 정렬된다.
- `title`은 굵게, `sub`는 아랫줄 보통 글씨. `\n`은 줄바꿈.
- 예시: `examples/orgchart_example.json` (3과제 × 2참여기관 + 공통 지원 3반 × 2기관).

## 문구 원칙

- 기관명·직위·역할 문구는 유저 원고를 그대로 쓴다. 칸이 좁아 줄여야 하면 유저에게 줄인 목록을 알린다.
- 직위를 모르면 지어내지 말고 유저가 준 표현(예: `직위 명기`)을 그대로 두거나 비워 두고 알린다.
- 표 아래 설명 불릿은 유저 원고가 있을 때만 붙인다.
